# Initial migrations design

## Background
- The backend defines SQLModel-based models for `users`, `items`, and `products` inside `backend/app/models.py`.
- There are currently no Alembic revisions; we need a clean initial migration that matches these models so we can manage future schema changes.
- The stack runs inside Docker Compose with the backend container already bootstrapped for `alembic` commands.

## Proposed solution (preferred approach)
1. Run `alembic revision --autogenerate -m "Initial models"` from within the backend container so Alembic compares the models metadata against the empty database. This will create the first revision under `backend/app/alembic/versions/` describing the `user`, `item`, and `product` tables with their columns, defaults, unique constraints, and foreign keys.
2. Verify the autogenerated revision matches the models (UUID primary keys, timestamps with UTC, unique indexes on email/product_id, relationships, etc.).
3. Run `alembic upgrade head` inside the container to ensure the migration applies cleanly and creates the tables (and capture the applied migration id for documentation).
4. Commit the new revision file so future schema changes can build on it.

Alternative approaches (not recommended)
- Manually author the initial migration (higher effort, greater risk of drift).
- Skip migrations and enable `SQLModel.metadata.create_all` (loses version history and deviates from the desired workflow).

## Verification
- `alembic upgrade head` should succeed without errors and report the new revision as applied.
- `SELECT table_name FROM information_schema.tables` inside the DB should list `user`, `item`, and `product` tables once the migration runs.
